# Как показать курсовую преподавателю

Для показа кода и настоящего развёртывания достаточно браузера и входа в свой GitHub. На компьютер ничего устанавливать не требуется. Глава 3 объясняет устройство проекта, а GitHub Actions запускает его и показывает результат проверок.

## 1. Сначала покажите связь текста и кода

Откройте главу 3 в Word. В подразделах 3.1.1–3.1.6 каждый компонент разобран в порядке: описание назначения, код основных функций, блок-схема, связное описание алгоритма. У quarantine-service отдельно рассмотрены восстановление и окончательное удаление.

Затем откройте [репозиторий проекта](https://github.com/Vitaly127-svg/ubi060-delete-guard). Листинги взяты из этих файлов:

| Что показывать | Где открыть |
|---|---|
| Шлюз, проверка токена и маршрутизация | [deploy/nginx.conf](../deploy/nginx.conf) |
| HTTP-обработчики микросервисов | [app/api.py](../app/api.py) |
| JWT и подписанный эталон | [app/security.py](../app/security.py) |
| Правила R1–R5, удаление, восстановление, аудит и чтение | [app/domain.py](../app/domain.py) |
| Доставка событий RabbitMQ | [app/messaging.py](../app/messaging.py) |
| Развёртывание и сетевые правила из 3.2 | [deploy/k8s](../deploy/k8s) и [scripts/deploy.sh](../scripts/deploy.sh) |

Можно объяснить общий путь так: «Запрос приходит через шлюз, токен подтверждает пользователя, guard проверяет условия удаления. Разрешённые данные сначала помещаются в карантин. Их можно восстановить до окончательного удаления. Каждое решение фиксируется в журнале».

## 2. Покажите уже выполненный запуск

Откройте [успешный Kubernetes smoke test](https://github.com/Vitaly127-svg/ubi060-delete-guard/actions/runs/41300664655). Нажмите **cluster**. В списке шагов раскройте **Deploy actual PostgreSQL Cassandra RabbitMQ and services**: там видны развёртывание и готовность компонентов.

Затем раскройте **Verify HTTPS and deletion lifecycle**. В нём находятся результаты 13 действий: вход владельца и администратора, чтение, карантин, повтор запроса, скрытие данных, восстановление, отказ при наличии ссылок, блокировка изменённой политики, окончательное удаление и проверка журнала.

У каждого действия есть `status` — полученный HTTP-код, `expected` — ожидаемый и `ok: true` — совпадение. Ответы 403, 409 и 410 в соответствующих шагах показывают работу защиты. Итог `all_passed: true` означает, что сценарий прошёл полностью.

## 3. Запустите проект заново при преподавателе

1. Войдите в аккаунт **Vitaly127-svg** и откройте [Kubernetes smoke test](https://github.com/Vitaly127-svg/ubi060-delete-guard/actions/workflows/cluster.yml).
2. Нажмите **Run workflow** справа над списком запусков.
3. Оставьте ветку **main** и нажмите зелёную кнопку **Run workflow**.
4. Откройте появившийся запуск, затем **cluster**. Дождитесь выполнения: подготовка кластера занимает несколько минут.
5. Покажите те же два шага развёртывания и проверки. Зелёная отметка всего запуска подтверждает успешное завершение.

Это настоящий временный Kubernetes-кластер с NGINX, PostgreSQL, Cassandra и RabbitMQ на машине GitHub. После проверки он автоматически останавливается. Постоянного адреса работающего приложения этот запуск не создаёт. Для следующего показа снова нажмите Run workflow.

Внизу страницы завершённого запуска находится **Artifacts → cluster-verification**. При необходимости можно скачать архив: `demo.json` содержит результаты, `pods.txt` — компоненты кластера, а файлы `.log` — журналы. Новые запуски также сохраняют `demo-report.html` — отчёт на русском, который открывается после распаковки архива. Для обычного показа достаточно раскрыть шаги в браузере.

## 4. Если нужен запуск именно на своём Windows-компьютере

Этот вариант дополнительный. Он запускает пять Python-сервисов с HTTP API и SQLite; работу NGINX, Cassandra, RabbitMQ и Kubernetes показывает кластерный сценарий выше.

1. На [главной странице репозитория](https://github.com/Vitaly127-svg/ubi060-delete-guard) нажмите **Code → Download ZIP**.
2. Распакуйте архив. Откройте полученную папку: в ней должен находиться файл **START_DEMO.cmd**. Из окна архива запускать его не нужно.
3. Установите **Python 3.12 для Windows**, если его ещё нет. Скачайте установщик с [официальной страницы Python 3.12.10](https://www.python.org/downloads/release/python-31210/), выбрав **Windows installer (64-bit)**. При установке отметьте **Add python.exe to PATH**.
4. Дважды нажмите **START_DEMO.cmd**. При первом запуске нужен Интернет для установки библиотек. Скрипт создаёт окружение `.venv` внутри папки проекта.
5. Дождитесь завершения. Скрипт запускает сервисы, выполняет реальные HTTP-запросы и открывает в браузере **отчёт на русском языке** с результатами всех шагов.

Покажите преподавателю, что чтение сначала разрешено, после карантина закрыто, после восстановления снова разрешено, а изменённая политика и входящие ссылки препятствуют удалению. Код и ожидаемый результат каждой операции стоят рядом в таблице.

Результаты сохраняются в `artifacts/demo-report.html` и `artifacts/local-smoke.json`. После автоматической проверки процессы останавливаются. Для нового показа снова запустите START_DEMO.cmd: создаётся новый тестовый набор данных. Если появится ошибка, окно останется открытым; по её тексту можно определить причину.

## Что сказать про состав работы

«В главе 3.1 показаны основные функции каждого микросервиса с кодом, блок-схемой и алгоритмом. В главе 3.2 находятся контейнеризация, манифесты, пространства имён и сетевые ограничения. Исходный код и сценарий развёртывания размещены в GitHub. Работа проверяется повторяемым запуском через Actions; локальный запуск используется для демонстрации функций на компьютере».
